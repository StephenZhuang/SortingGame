# 猜瓶子 App 图标设计

## 1. 目标

为「猜瓶子」提供三端（iPhone / iPad / macOS）桌面应用图标，替换当前两个 target 中只有 `Contents.json` 占位、无任何图片的 `AppIcon.appiconset`。

图标承担单一职责：在桌面最小尺寸（锁屏 29pt）下也能一眼识别出「瓶 + 排序」的游戏主题，并与游戏内视觉同源。

## 2. 视觉设计

### 2.1 构图

- 画布 1024×1024，满幅方形；**画面内不画圆角、不加超出画框的外部投影**（圆角由 iOS / macOS 系统遮罩生成）
- 主体：横向 4 格分隔的深色盒子，位于画面中部偏下，采用轻微仰视透视
- 每格立一只瓶子，四只瓶子等高、等距，构成「一排待排序的元素」这一核心意象
- 全部内容收在中心约 82% 安全区内，避免被系统遮罩切边
- 定稿主体填充率约 **72%**（四边各留白约 14%）：初版生成为 56%，缩到 87pt 以下时留白过多、主体发空，故对主图做中心裁切放大

### 2.2 色彩

- 背景：深靛蓝 → 深紫的对角微渐变，中心叠一层弱径向光，把瓶子从背景中推出
- 瓶身：按游戏内色表 `BottleStyle.color(forIndex:)` 取前 4 色 —— 红、蓝、绿、橙
- 瓶身符号：`● ■ ▲ ★`，按 `BottleStyle.shapeSymbol(forIndex:)` 顺序对应
- 符号描色遵循 `BottleStyle.symbolColor(forIndex:)`：深底（红、蓝）用白符号，浅底（绿、橙）用黑符号
- 质感：瓶身为带高光的立体玻璃/塑料质感，盒内有柔和投影；图标色彩观感与游戏内一致即可，不要求色值逐位相同

### 2.3 硬性约束

- 纯图形，**不出现任何文字、字母、数字、水印**
- 图标不引入与游戏无关的元素（无手指、无箭头、无星星装饰等）

## 3. 产出物与落位

| 位置 | 内容 |
|------|------|
| `docs/assets/app-icon-1024.png` | 定稿 1024×1024 主图，作为后续派生各尺寸的单一真源 |
| `SortingGame-iOS/Assets.xcassets/AppIcon.appiconset/` | 单张 universal 1024；`Contents.json` 仅保留该槽位 |
| `SortingGame/Assets.xcassets/AppIcon.appiconset/` | 由主图派生 16/32/128/256/512 各 1x/2x 共 10 张，文件名写入 `Contents.json` |

`Contents.json` 中 iOS 的 dark / tinted 两个空槽条目一并移除，只保留 default 单槽，避免打包时的空图标槽告警。

## 4. 候选与定稿方式

先用 ImageGen 产出 2–3 张 1024 候选主图，由用户在真机/桌面观感中挑选一张定稿；未定稿前不写入 `appiconset`。

生成图有两条必须处理的坑（本次实证）：

1. 右下角带「Qoder AI 生成」水印文字，与「无文字」硬约束冲突。定稿后需对水印区域做逐行背景插值 + 羽化模糊修复（水印落在平滑渐变上，修复无痕）
2. 模型常把圆角直接画进画面、四角留白块。必须挑满幅无白角的候选，否则桌面会出现双重圆角白边

## 5. 验证

1. `xcodebuild` 编译 iOS（`SortingGame-iOS` scheme + generic simulator destination）与 macOS target，确认图标资源被打包、无空槽告警
2. 桌面 / 模拟器实际观感由用户回报确认（本机无 GUI 截图权限）
3. 检查最小尺寸可读性：主图缩到 29pt 与 16pt 后瓶子轮廓与分隔格仍可辨

## 6. 明确不做

- dark / tinted 双变体图标
- Launch Screen、Game Center、App Store 营销图等其他图标资产
- 矢量绘制脚本与图标生成工具链
